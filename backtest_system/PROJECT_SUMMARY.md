# 项目总结

## 系统架构

本回测系统采用模块化设计，分为五个核心模块：

```
                    ┌─────────────────┐
                    │   主控制器      │
                    │   (main.py)     │
                    └────────┬────────┘
                             │
          ┌──────────────────┼──────────────────┐
          │                  │                  │
    ┌─────▼─────┐    ┌──────▼──────┐    ┌─────▼─────┐
    │ 数据加载  │    │   优化器    │    │  执行器   │
    │  模块     │    │   模块      │    │   模块    │
    └─────┬─────┘    └──────┬──────┘    └─────┬─────┘
          │                  │                  │
          └──────────────────┼──────────────────┘
                             │
                      ┌──────▼──────┐
                      │  统计模块   │
                      │ (metrics)   │
                      └─────────────┘
```

## 核心功能

### 1. 数据加载模块 (data_loader/)

**设计特点：**
- 大小文件分离：大文件（aggtrade）按需加载，小文件（signal）一次加载
- 缓存机制：避免重复加载同一时间段数据
- 扩展接口：支持自定义数据加载器

**关键类：**
- `BaseLoader`: 所有加载器的基类
- `LargeFileLoader`: 大文件加载器基类（按需加载）
- `SmallFileLoader`: 小文件加载器基类（一次性加载）
- `AggTradeLoader`: Binance成交数据加载器
- `SignalLoader`: 信号数据加载器
- `FundingRateLoader`: 资金费率数据加载器

### 2. 优化模块 (optimizer/)

**设计特点：**
- 策略解耦：优化逻辑与执行逻辑分离
- 易于扩展：继承BaseOptimizer即可实现自定义策略
- 防止未来函数：确保只使用当前或过去的数据

**关键类：**
- `BaseOptimizer`: 优化器基类
- `SimpleOptimizer`: 简单线性优化器示例

**输入：**
- 当前时间
- 信号值字典
- 当前仓位字典
- 当前价格字典
- USDT保证金余额

**输出：**
- 目标仓位字典（正数多仓，负数空仓）

### 3. 执行模块 (executor/)

**设计特点：**
- 真实模拟：考虑延迟、滑点、手续费
- 成交限制：不超过市场成交量的指定比例
- VWAP成交：在时间窗口内按VWAP价格成交

**关键参数：**
- `execution_delay`: 执行延迟（秒）
- `execution_window`: 成交窗口（秒）
- `fee_rate`: 手续费率
- `slippage_rate`: 滑点率
- `max_volume_pct`: 最大成交量占比

**执行流程：**
1. 计算目标仓位与当前仓位差异
2. 在延迟后的时间窗口内获取VWAP
3. 应用滑点计算实际成交价
4. 检查成交量限制
5. 计算手续费和PnL
6. 更新仓位和余额

### 4. 资金费率模块

**功能：**
- 自动识别资金费率结算时间（通常每8小时）
- 精确到毫秒级的时间匹配
- 多空仓位分别计算

**结算逻辑：**
- 多仓支付资金费率（PnL为负）
- 空仓收取资金费率（PnL为正）
- 公式：`PnL = -仓位价值 × 资金费率`

### 5. 统计模块 (metrics/)

**输出内容：**

**trade_log.csv（交易明细）：**
- start_time: 周期开始时间
- end_time: 周期结束时间
- symbol: 交易对
- target_quantity: 目标数量
- actual_quantity: 实际成交数量
- vwap: VWAP价格
- execution_price: 执行价格（含滑点）
- trade_value: 交易金额
- fee: 手续费
- slippage: 滑点

**position_log.csv（仓位状态）：**
- time: 时间点
- usdt_balance: USDT保证金
- trade_pnl: 本周期交易PnL
- hold_pnl: 本周期持有PnL
- fee_pnl: 本周期手续费PnL
- funding_pnl: 本周期资金费率PnL
- total_pnl: 本周期总PnL
- {symbol}_position: 各币种仓位
- {symbol}_price: 各币种价格

## 时间处理

**统一使用UTC时区：**
- 所有时间均为UTC
- 使用`datetime.fromtimestamp(ts, tz=timezone.utc)`
- 避免本地时区混淆

**时间戳单位：**
- 可配置为秒(s)或毫秒(ms)
- aggtrade默认：毫秒
- signal默认：毫秒
- funding_rate默认：毫秒

## PnL计算详解

每个周期的总PnL分为四个部分：

### 1. Trade PnL（交易盈亏）
新开仓位从执行价到周期结束价的盈亏
```
trade_pnl = 成交数量 × (周期结束价 - 执行价)
```

### 2. Hold PnL（持有盈亏）
原有仓位从周期开始价到结束价的盈亏
```
hold_pnl = 原有仓位 × (周期结束价 - 周期开始价)
```

### 3. Fee PnL（手续费）
交易产生的手续费（负数）
```
fee_pnl = -交易金额 × 手续费率
```

### 4. Funding PnL（资金费率）
资金费率结算产生的盈亏
```
funding_pnl = -仓位价值 × 资金费率
```

**保证金更新：**
```
下一周期保证金 = 当前保证金 + total_pnl
total_pnl = trade_pnl + hold_pnl + fee_pnl + funding_pnl
```

## 回测流程

```
开始
  │
  ├─> 记录初始状态（t0）
  │
  ├─> For each 时间点 t:
  │     │
  │     ├─> 1. 结算资金费率
  │     │
  │     ├─> 2. 检查爆仓
  │     │     └─> 如果保证金≤0，清空所有仓位
  │     │
  │     ├─> 3. 更新当前价格
  │     │
  │     ├─> 4. 获取信号值
  │     │
  │     ├─> 5. 优化：计算目标仓位
  │     │
  │     ├─> 6. 执行交易
  │     │     ├─> 延迟
  │     │     ├─> VWAP成交
  │     │     ├─> 应用滑点
  │     │     └─> 计算手续费
  │     │
  │     ├─> 7. 更新仓位和余额
  │     │
  │     ├─> 8. 记录交易明细
  │     │
  │     ├─> 9. 更新周期结束价格
  │     │
  │     ├─> 10. 计算PnL
  │     │
  │     ├─> 11. 更新保证金
  │     │
  │     └─> 12. 记录周期状态
  │
  └─> 保存结果
```

## 性能优化建议

1. **数据加载：**
   - 按天或按周加载数据
   - 使用缓存机制
   - 只加载必要的时间范围

2. **日志级别：**
   - 开发阶段：DEBUG
   - 生产运行：INFO或WARNING

3. **回测参数：**
   - 先用小时间段测试
   - 减少交易对数量
   - 增大回测频率

4. **内存管理：**
   - 定期清理缓存
   - 使用生成器处理大数据
   - 避免在内存中保留全部历史数据

## 注意事项

### 防止未来函数
- 优化模块只能使用当前或过去的数据
- 信号取最近的过去时间点
- 价格使用指定时间之前的最后成交价

### 爆仓处理
- 保证金≤0时触发爆仓
- 所有仓位清零
- 继续运行但不再交易

### 资金费率
- 自动识别结算时间（允许1秒偏差）
- 在优化前结算
- 影响保证金余额

### 成交限制
- 单笔交易不超过市场成交量的指定比例
- 如果超限，按比例缩减
